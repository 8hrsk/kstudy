# kstudy — контекст проекта

Файл читается Claude Code при старте сессии. Здесь всё, что нужно, чтобы
продолжить работу с нуля: цель, механизм, состояние, текущий блокер и правила,
которые нельзя нарушать.

Развёрнутые рассуждения — в `docs/`. Сюда вынесено только то, без чего нельзя
принимать решения.

## 1. Что это за проект

Исследовательский стенд для одного вопроса:

> **Можно ли численно отличить конспект, в котором модель что-то поняла, от
> конспекта, в котором она переписала слова, — не имея правильного ответа?**

Зачем это нужно. Долгосрочная цель владельца — модель, которая изучает корпус
документации днями и становится экспертом в узкой области (low-level
разработка, потом научные домены). Для верифицируемых доменов петля замыкается
компилятором и тестами. Для неверифицируемых верификатора нет — и весь вопрос
в том, чем его заменить.

Ответ, который проверяется: **сжатием и согласованностью**. Человек, читающий
теорию без учителя, опирается на четыре внутренних сигнала (раздел 3). Все
четыре вычислимы. Если они дают достаточно сигнала, метод переносится на
домены без верификатора.

Ничего пока не обучается. Э1 — только измерения. Если метрика не коррелирует с
человеческой оценкой, вся программа не имеет смысла, и лучше узнать это за
неделю, чем за полгода.

| Претрейн малой модели с нуля | ~100 млрд+ токенов до связного tool-calling, результат хуже готовой Qwen3-0.6B. Берём готовую базу. |
| Забывание ради освобождения ёмкости | Трансформер хранит ~2 бита знания на параметр (Allen-Zhu & Li). 7B ≈ 14 Гбит — больше, чем Википедия с учебниками. Домен влезает без чистки. Узкое место — число повторений факта, а не место. |
| Обучение только на доменном корпусе | AdaptLLM: сырой корпус даёт знание, но ломает способность отвечать. Нужна примесь general instructions 10–30 %. |
| Поверхностный MDL как основная метрика | Структурно поощряет копирование, см. раздел 3. Оставлен как второстепенный сигнал. |
| Подбор λ | λ=1 — «честный MDL без свободных параметров», это главное достоинство схемы. Трогать в последнюю очередь и с явной оговоркой. |

Что осталось живым: замороженное ядро + растущая память, многочастотная
консолидация, забывание как активный механизм, самоулучшение через петлю с
внешним верификатором там, где он есть.

## 3. Механизм

### Четыре сигнала, заменяющие проверку

Человек, читающий теорию без учителя, использует:

1. **Предсказание и его ошибка** — верификатором служит сам текст.
2. **Согласованность с известным** — противоречие детектируется внутри.
3. **Способность восстановить** — конспект позволяет породить содержание.
4. **Способность инстанцировать** — из общего вывести частный случай.

Сигналы 1 и 3 — одно и то же с двух сторон: потеря предсказания следующего
токена *есть* длина префиксного кода (prequential coding). Понимание = сжатие.
Производная сжатия по времени — compression progress Шмидхубера, формальное
определение любопытства.

### Триаж: учебный план, который ничего не стоит

Два числа с одного forward-прохода:

```
L_base = -log₂ P(C)              насколько чанк удивителен сам по себе
L_info = -log₂ P(C | заметки)    насколько помогает уже накопленное
Δ      = L_base - L_info
```

| L_info/ток | Δ/L_base | класс | действие |
|---|---|---|---|
| низкая | — | `known` | пропустить, генерацию не тратить |
| высокая | высокая | `zpd` | зона ближайшего развития, учить сейчас |
| высокая | ≈ 0 | `too_far` | отложить, нужны предпосылки |

Порог «известного» берётся по `L_info`, **не** по `L_base`: последняя не знает,
что модель уже прочитала.

### Основная метрика: закрытый экзамен

```
выигрыш = [ L(A|Q) − L(A|Q,N) ] − λ·L(N)        λ = 1
```

Вопросы составляются **по чанку** (чанк в контексте — это извлечение,
безопасная операция), отвечать модель обязана **без чанка**.

Почему именно так, а не MDL на поверхности текста. Строгий MDL спрашивает
«дешевле ли передать заметку плюс чанк при заметке, чем чанк напрямую». Для
этой задачи дословная копия почти оптимальна: платим `L(C)` за копию и ≈0 за
чанк. Замер на CPU-стенде подтвердил:

| заметка | экономия | поверхностный выигрыш |
|---|---|---|
| копия | 95.9 % | −27 бит |
| осмысленная сжатая | 39.0 % | −227 бит |

Экзамен это чинит через **насыщение**: польза ограничена сверху `Σ L(A|Q)`, а
цена растёт с длиной. Копия, будучи втрое дороже, не может быть втрое полезнее.

## 4. Состояние кода

```
kstudy/
  scoring.py    Scorer: HFScorer (transformers) | CacheNgramScorer (тесты, без GPU)
  metrics.py    L_base, Δ, триаж, NoteMetrics (поверхностный), TaskNoteMetrics (экзамен)
  corpus.py     нарезка подсистемы ядра по смысловым границам; пресеты SUBSYSTEMS
  notes.py      генерация заметок и экзаменов, контроли, verbatim_overlap/exam_leakage
  rate.py       CLI ручной разметки
  analyze.py    Spearman с бутстрэпом, AUC, разделение контролей
  _compat.py    UTF-8 консоль и POSIX-пути для Windows
scripts/
  fetch_corpus.py  разреженная выборка каталогов ядра
  smoke_gpu.py     проверки A–E на настоящей модели
tests/
  test_metrics.py  19 инвариантов, без GPU, секунды
run_e1.py       весь этап одной командой
docs/           история рассуждений, четыре документа + оглавление
```

`CacheNgramScorer` — игрушечная LM из трёх компонент: n-грамма с backoff, кэш
по контексту, суффиксное совпадение. Третья принципиальна: без неё дословная
копия экономит ~20 % бит, тогда как настоящий трансформер ~95 % за счёт
индукционных голов.

**Чего игрушка проверить не может:** знак выигрыша на реальных текстах. У
слабой LM биты/токен почти одинаковы для любого текста (замер: 12.3 у гладкой
заметки против 11.0 у плотного технического чанка). Вся дискриминация держится
на том, что у настоящей модели разрыв кратный. Отсюда проверка A в смоуке.

Тесты: 24/24 проходят. Прогонять `python tests/test_metrics.py` перед любым
коммитом — они трижды ловили содержательные ошибки в метрике.

## 5. ГДЕ МЫ СЕЙЧАС

Разбор провала A и C — в `docs/e1-debug-A-C.md` (задание с гипотезами H1–H5).
Результаты шагов 1–3 — в `docs/e1-results-step1-2.md`. Здесь только итог.

### Что было и что стало

Первый прогон `smoke_gpu.py` на Qwen3-1.7B провалил A и C. Разбор дал пять
гипотез. Шаг 1 (измерить, ничего не меняя) выполнен — `scripts/diagnose_ac.py`:

| | итог | число |
|---|---|---|
| H1 потолок ниже цены заметки | **подтверждена, решающая** | база/L(N) = 1.03× |
| H2 модель знает RCU | **тест не различает** | RCU/заведомо новый = 0.96× |
| H3 дорогой стиль заметки | подтверждена в б/т | телеграф/проза = 1.29× |
| H4 экзамен смоука течёт | **отклонена** | leakage 0.0 % |

**H1 объясняла провал C целиком:** база 590.4 бита против `L(N)` 571.7,
потолок выигрыша +18.7 бита. C не могла пройти ни при каком качестве заметки.

Шаг 2 применён (экзамен 4 → 16 вопросов, гейт `MIN_EXAM_HEADROOM = 3.0`).
Порядок перевернулся: на 4 вопросах копия давала больше экономии и recall,
чем осмысленная заметка; на 16 — заметка обходит копию по всем показателям.

**Шаг 3 отменён измерением.** H3 верна в битах на токен, но `task_gain`
вычитает `L(N)` в абсолютных битах, а проза длиннее. Прогон трёх стилей
через экзамен: телеграфный выигрывает и по цене, и по экономии (299.5 против
190.6). Правка сделала бы хуже. `NOTE_PROMPT` не тронут.

**Шаг 4 не обоснован:** тест H2 не отделяет знакомый текст от незнакомого —
весь разброс 1.17×, а заведомо не бывший в претрейне текст стоит столько же,
сколько RCU. Смена корпуса — самая дорогая правка, делать её на этих данных
нельзя. Нужен честный контроль: незнакомая техническая **проза**, не код.

### Прогон на 40 чанках — `docs/e1-run40-results.md`

33 чанка дожили до метрик (один отсев по утечке, шесть по гейту headroom).

```
тип          n   медиана   среднее   доля>0        recall    lev    L(N)
model       33     120.9     122.4      73 %       26.5 %   1.33     426
copy        33      26.9     -99.2      55 %       47.8 %   1.05     825
water       33    -124.7    -135.3       0 %        5.0 %   0.46     231
unrelated   33    -753.9    -753.4       0 %        4.8 %   0.11     825
```

**Мусор отсекается полностью:** ни один из 66 контролей не дал положительного
выигрыша. **C.2 закрыта:** заметка окупается на 24 чанках из 33.

**Но C.1 держится слабо: попарно model > copy лишь 18/33 = 55 %.** Медианы
обманывают — у копии тяжёлый левый хвост на длинных чанках, а на коротких она
окупается. Копия закрывает экзамен **лучше** заметки (recall 47.8 % против
26.5 %); заметка выигрывает только ценой.

Это значит, что **насыщение не наступило**: замысел был в том, что польза
упирается в потолок `Σ L(A|Q)` и копия не может быть вдвое полезнее, будучи
вдвое дороже. При recall копии 47.8 % до потолка далеко. Нужен экзамен, на
котором копия упирается в потолок — сложнее и длиннее 16 вопросов, с
вопросами на вывод, а не на извлечение.

**Про A.** Она сравнивает биты на токен, а `task_gain` вычитает `L(N)` в
абсолютных битах — величины, которой в A нет. Конспект несёт то же содержание
меньшим числом токенов, поэтому цена за токен растёт почти по определению
сжатия, а суммарная падает. Лучший из трёх стилей всё равно не даёт 1.25×.
Похоже, A требует невозможного. Порог **не сдвинут**, провал не отменён,
рядом добавлена A2 — решение о переспецификации за человеком.

### Открытый вопрос

Вода даёт 97.9 бита экономии при нулевом содержании: любой текст в контексте
задаёт домен и стиль. У `good` из 299.5 бита около трети — этот базовый
уровень. Если разделение контролей останется слабым на сорока чанках,
напрашивается вычитать экономию воды. Это изменение метрики — сначала числа.

### Запасной план

Если C.2 не закрывается — не спасать λ, а сменить схему сравнения: **равный
бюджет** (скажем, 80 токенов) всем заметкам и сравнение только по recall.
Копия в бюджет не влезает и теряет хвост, который экзамен спросит. Никакого λ.
Теряется изящество «понимание = сжатие», но схему труднее сломать.
Сейчас применять преждевременно: C.1 только что заработала.

## 6. Правила, которые нельзя нарушать

Каждое куплено ошибкой. Нарушение любого делает измерения бессмысленными.

**Измерения**

- Пороги решения заданы заранее: **ρ ≥ 0.5 и AUC ≥ 0.75** — идти в Э2;
  ρ 0.3–0.5 — чинить метрику; ρ < 0.3 — гипотеза не подтвердилась.
  **Не двигать после того, как увидели числа.**
- λ = 1 — не настройка, а свойство схемы. Изменение документировать в README.
- Held-out откладывается **до** генерации синтетики, иначе оценка ничего
  не значит.
- Отложенная часть корпуса не участвует ни в заметках, ни в экзаменах.

**Экзамены и заметки**

- Экзамен составляется по чанку, отвечать — без чанка.
- Ответы обязаны быть перефразированы. Дословный ответ превращает метрику в
  проверку запоминания, и копия выигрывает механически. Мерить `exam_leakage`,
  порог 0.25.
- Заметка сравнивается с тремя контролями: копия, вода, чужая заметка. Без них
  непонятно, различает ли метрика вообще что-нибудь.

**Разметка**

- `rate.py` перемешивает порядок и скрывает тип заметки. Если разметчик знает,
  что перед ним копия, корреляция становится артефактом.
- Оценивается один вопрос: «если бы источник исчез, а осталась только эта
  заметка, много ли потеряно?» Не стиль, не полнота.

**Техническое**

- `core.autocrlf=false`. Перевод строки меняет токенизацию и число бит, то
  есть портит измеряемые величины. Корпус качать только `scripts/fetch_corpus.py`.
- Весь файловый ввод-вывод с явным `encoding="utf-8"` — иначе Python на Windows
  берёт кодировку из локали.
- Пути в `chunk_id` нормализованы через прямые слэши, иначе один файл даёт
  разные id на разных ОС и прогоны перестают сравниваться.
- `HFScorer` при переполнении контекста режет **только контекст, никогда
  target** — иначе биты между чанками несравнимы.
- `logits[i]` предсказывает токен `i+1`. Ошибка на единицу даёт правдоподобные,
  но неверные числа. Проверка B в смоуке ловит именно это.

## 7. Дорожная карта

- **Э0** Измерительный стенд, базовые линии. ✅ сделано
- **Э1** Метрики без эталона: коррелируют ли с человеческой оценкой.
  ⏳ **здесь, заблокировано провалом A и C**
- **Э2** Триаж и генерация: при равном бюджете триаж должен бить равномерную
  генерацию.
- **Э3** Замкнуть петлю: обучение с весами по превышению потери (схема RHO-1,
  но референс — собственный прошлый чекпойнт), замер learning progress.
  Ожидаемое плато на 2–3 итерации.
- **Э4** **Главный эксперимент.** Один пайплайн, две ветки на верифицируемом
  домене: A — с компилятором и тестами в петле, B — только MDL-реконструкция и
  граф согласованности. Обе оценивать компилятором. Получится число: какую долю
  настоящего верификатора добирает проверка без эталона. 80–90 % — метод
  переносится на неверифицируемые домены; 30–40 % — знаете цену; ~0 — гипотеза
  мертва, и это выяснено за месяц, а не за год.
- **Э5** Перенос на домен без верификатора. Только если Э4 дал приличное число.

Э4 требует WSL2: `herd7` из LKMM (OCaml), сборка ядра, `qemu`, `vllm`.
Подсистема `memory-model` в `SUBSYSTEMS` выбрана под это — литмус-тесты
машинно проверяемы.

## 8. Окружение и команды

Машина: Windows 11, Ryzen 7, **RTX 3060 12 ГБ**, 32 ГБ RAM. Есть возможность
арендовать GPU.

Что влезает в 12 ГБ: инференс 4–8B в 4 бита; QLoRA на 7–8B; полный файнтюн 1B
в bf16 впритык (8-bit Adam + gradient checkpointing). Полный CPT 3–7B — аренда.

Батчевая генерация на 3060: 8B 4-bit ~300–600 ток/с агрегатно, 4B до ~1200.
100M токенов синтетики ≈ трое суток. Локальная генерация жизнеспособна.

```bash
python tests/test_metrics.py                                   # без GPU, секунды
python scripts/fetch_corpus.py --subsystem rcu --dest ./linux
python scripts/smoke_gpu.py --model Qwen/Qwen3-1.7B            # точка невозврата
python scripts/diagnose_ac.py --kernel ./linux                 # H1–H4, ничего не меняет
python run_e1.py --kernel ./linux --subsystem rcu --n-chunks 40
python -m kstudy.analyze data/metrics.jsonl                    # контроли, без разметки
python -m kstudy.rate data/notes.jsonl data/chunks.jsonl
python -m kstudy.analyze data/metrics.jsonl --ratings data/ratings.jsonl
```

Windows: подробности и грабли — в `WINDOWS.md`. Кратко: обычный `git clone`
ядра ломается о коллизии регистра в netfilter (`xt_CONNMARK.h` /
`xt_connmark.h`), длинные пути и autocrlf — поэтому только `fetch_corpus.py`.

## 9. Как со мной работать

- **Не подгонять под результат.** Если метрика не работает — это результат, и
  его надо записать, а не спасти подбором параметров. Отрицательный ответ за
  месяц дороже положительного за год.
- **Сначала измерить, потом чинить.** Дважды в этом проекте тесты вскрывали
  содержательные ошибки, которых не было видно в рассуждениях.
