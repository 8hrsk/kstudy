# Э1: прогон на 40 чанках

`run_e1.py --kernel ./linux --subsystem rcu --n-chunks 40`, Qwen3-1.7B, RTX 3060.
Продолжение `e1-results-step1-2.md`. Все числа — с гейтом headroom ≥ 3.0
и экзаменом на 16 вопросов.

---

## 1. Что дошло до метрик

```
548 чанков подходящего размера -> 40 взято
 40 -> 39   один отсев: утечка экзамена 25 % (чанк 22)
 39 -> 33   шесть отсеяны гейтом headroom < 3.0  (15 %)
 33 чанка x 4 вида заметки = 132 строки
```

Триаж разделил корпус на три почти равные части, что само по себе
осмысленно — если бы всё падало в один класс, он не нёс бы информации:

```
пороги: known_below = 3.35 б/т,  delta_frac_min = 0.043
too_far 14 | known 13 | zpd 13
```

Гейт headroom отсеял 15 % — не ноль и не половина, то есть работает как
фильтр, а не как формальность. У прошедших чанков headroom от 3.08 до 8.48,
медиана 4.69.

## 2. Главный результат: мусор отсекается полностью

```
тип          n   медиана   среднее   доля>0
model       33     120.9     122.4      73 %
copy        33      26.9     -99.2      55 %
water       33    -124.7    -135.3       0 %
unrelated   33    -753.9    -753.4       0 %
```

**Ни один из 66 мусорных контролей не дал положительного выигрыша.**
Ни вода, ни чужая заметка не прошли ни на одном чанке. Это сильнее, чем было
на смоуке, и это первое, что должна уметь метрика.

**C.2 закрыта на реальных данных.** На смоуке хорошая заметка не окупалась
(−272.2). Здесь модельная заметка окупается на 24 чанках из 33 — медиана
+120.9 бита, вердикт `keep` у 24, `weak` у 9. Отрицательных нет.

## 3. Оговорка, которую скрывают медианы

Медианы говорят «model 120.9 против copy 26.9», разрыв в пять раз. Попарное
сравнение на одном и том же чанке говорит другое:

```
попарно model > copy:  18/33 = 55 %
```

Пятьдесят пять процентов — чуть лучше монетки. Агрегат выглядит убедительно
только потому, что у копии тяжёлый левый хвост: на длинных чанках она платит
огромный штраф и утягивает среднее в −99.2, тогда как медиана у неё
положительная (+26.9), и на коротких чанках копия окупается.

Почему так, видно из разложения:

```
тип        recall     lev    L(N)   verbatim
model       26.5 %   1.33     426       0 %
copy        47.8 %   1.05     825     100 %
water        5.0 %   0.46     231       0 %
unrelated    4.8 %   0.11     825       0 %
```

**Копия закрывает экзамен почти вдвое лучше модельной заметки** — 47.8 %
против 26.5 %. Выигрывает заметка только за счёт цены: 426 бит против 825, и
`leverage` 1.33 против 1.05.

Это ровно тот механизм, ради которого вводился экзамен, — но он работает не в
полную силу. Замысел был в **насыщении**: польза упирается в потолок
`Σ L(A|Q)`, поэтому копия, будучи вдвое дороже, не может быть вдвое полезнее.
При recall копии 47.8 % до потолка ещё далеко, насыщение не наступило, и
копия пока проигрывает не по существу, а по штрафу за длину.

Чтобы механизм заработал как задумано, экзамен должен быть такой, чтобы копия
на нём **упиралась в потолок** — то есть заметно сложнее и длиннее нынешних
16 вопросов, либо с вопросами, требующими вывода, а не извлечения.

## 5. Чего ещё нет

**Корреляции с человеческой оценкой — главного числа Э1 — нет.** Пороги
раздела 6 CLAUDE.md (ρ ≥ 0.5, AUC ≥ 0.75) на контролях не проверяются:
контроли показывают лишь, что метрика различает заведомо разное. Нужна ручная
разметка:

```bash
python -m kstudy.rate data/notes.jsonl data/chunks.jsonl
python -m kstudy.analyze data/metrics.jsonl --ratings data/ratings.jsonl
```

Это примерно час работы человека, и его нельзя делегировать: разметчик должен
быть тем, кто принимает решение о переходе в Э2.

Осторожность перед разметкой: метрика уверенно отделяет осмысленное от
мусора, но внутри осмысленного различает слабо (55 %). Корреляция с
человеческой оценкой считается именно **внутри** осмысленного, поэтому
ожидать высокой ρ на этих данных не стоит. Возможно, разумнее сначала
поднять сложность экзамена и повторить прогон, а размечать уже после.
