# Запуск на Windows 11

## Коротко

**Э1 работает на Windows нативно.** Менять ОС не нужно. Ядро Linux мы не
собираем и не запускаем — берём из него только текстовые файлы как учебный
материал.

Смена ОС понадобится позже, на Э4, и там есть готовый ответ — WSL2.

---

## Зачем вообще ядро

Это **корпус**, то есть материал для изучения. Нужны:

- `Documentation/RCU/*.rst` — объяснения на человеческом языке
- `kernel/rcu/*.c` — исходники с комментариями-шапками

Они режутся на чанки и подаются модели. Ничего не компилируется, `make` не
запускается, заголовки ядра никуда не подключаются. С точки зрения кода это
просто папка с текстом.

Выбор ядра, а не любой другой документации, не случаен: рядом лежит
`tools/memory-model` с литмус-тестами, которые машинно проверяются `herd7`.
На Э4 это станет веткой A — «пайплайн с настоящим верификатором» против
ветки B без него.

## Три грабли Windows, и почему обычный `git clone` не подходит

### 1. Коллизии регистра

В netfilter лежат пары файлов, различающиеся только регистром:
`xt_CONNMARK.h` / `xt_connmark.h`, `xt_DSCP.h` / `xt_dscp.h`,
`xt_MARK.h` / `xt_mark.h` и другие. NTFS регистр не различает, поэтому второй
файл затирает первый, и git считает дерево грязным сразу после клонирования.

### 2. Длинные пути

Часть путей в ядре длиннее 260 символов — исторического лимита Windows.

### 3. Перевод строк

`core.autocrlf` по умолчанию превращает LF в CRLF. Для обычного проекта это
косметика, для нас — нет: лишний символ на строку меняет токенизацию и число
бит, то есть портит ровно те величины, которые мы меряем.

### Решение

`scripts/fetch_corpus.py` делает разреженную выборку: качает только нужные
каталоги. Netfilter при этом просто не скачивается, поэтому (1) и (2) исчезают;
(3) выключается явными флагами. Заодно вместо ~5 ГБ получается несколько
мегабайт.

## Установка

```powershell
# 1. Python 3.11+ и git
winget install Python.Python.3.12
winget install Git.Git

# 2. PyTorch с CUDA. Для RTX 3060 (Ampere) подходит cu124.
#    ВАЖНО: без --index-url ставится сборка без CUDA, и всё поедет на CPU.
pip install torch --index-url https://download.pytorch.org/whl/cu124
pip install transformers numpy

# 3. Проверить, что видеокарта видна
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
#    ожидается:  True NVIDIA GeForce RTX 3060

# 4. Корпус — несколько мегабайт вместо полного дерева
python scripts/fetch_corpus.py --subsystem rcu --dest .\linux

# 5. Инварианты метрики — без GPU, секунды
python tests\test_metrics.py

# 6. ГЛАВНАЯ ПРОВЕРКА
python scripts\smoke_gpu.py --model Qwen/Qwen3-1.7B

# 7. Полный прогон
python run_e1.py --kernel .\linux --subsystem rcu --n-chunks 40
```

### Терминал

Пользуйтесь Windows Terminal (в Windows 11 он по умолчанию), не старым
`cmd.exe`. Скрипты печатают рамки и галочки; в консоли с кодовой страницей
866/1251 это падает с `UnicodeEncodeError`. На всякий случай в коде стоит
`enable_utf8_console()`, но старый `cmd.exe` всё равно лучше не трогать.

Все чтения и записи файлов идут с явным `encoding="utf-8"` — иначе Python на
Windows берёт кодировку из локали и портит JSON.

## Когда всё-таки понадобится WSL2

На Э4, когда появится ветка A с настоящим верификатором. Там нужны:

- `herd7` из LKMM — это OCaml, на Windows ставится мучительно
- сборка кода ядра, `qemu`, `renode`
- `vllm` для батчевой генерации — под Windows официально не поддерживается,
  а именно на нём держится расчёт «100M токенов за трое суток»

Хорошая новость: **WSL2 на Windows 11 даёт полноценный доступ к 3060.** Это не
эмуляция, а прямой проброс через GPU-PV, и производительность близка к нативной.

Одно правило, нарушение которого ломает всё:

> **Драйвер NVIDIA ставится только на стороне Windows.** Внутри WSL2 ставится
> ТОЛЬКО CUDA Toolkit (`cuda-toolkit-12-x`), никогда не пакет драйвера.
> `sudo apt install cuda` затягивает линуксовый драйвер, затирает WSL-заглушку
> и убивает проброс.

```bash
wsl --install -d Ubuntu
# внутри Ubuntu:
nvidia-smi                      # должна показать 3060 без всякой установки
pip install torch --index-url https://download.pytorch.org/whl/cu124
```

Диск: держите репозиторий внутри файловой системы WSL (`~/kstudy`), а не в
`/mnt/c/...`. Через `/mnt/c` ввод-вывод медленнее в разы, а на чтении тысяч
мелких файлов это заметно.

## Стоит ли сразу перейти на WSL2

| | Windows нативно | WSL2 |
|---|---|---|
| Э1 (сейчас) | работает | работает |
| Скорость установки | быстрее | +30 минут настройки |
| `vllm`, батчевая генерация | нет | да |
| `herd7`, сборка ядра (Э4) | нет | да |
| Возня с путями и кодировками | есть, но обойдена | нет |

Разумно так: **Э1 запустить нативно прямо сейчас** — это меньше движений, а
ответ на главный вопрос нужен быстро. Если пройдёте порог и пойдёте в Э2,
переезжайте в WSL2 тогда: там вы всё равно окажетесь, а тащить туда мёртвую
гипотезу не придётся.
